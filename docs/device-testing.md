# 実機検証手順

ネイティブ層（`app/android/.../*.kt`、`app/ios/Runner/AppDelegate.swift`）は、この開発環境では実機で動かせていません。
検証状況: Kotlin = Android 15 APIに対してコンパイル確認のみ / Swift = **コンパイル未確認**。

## 事前準備
- Android: Android 10以上、Android Studio（または `flutter build apk --debug`）
- iOS: Xcode（iOS 15以上）。署名設定（Team）が必要
- `cd app && flutter pub get && flutter run`

## チェックリスト（上から順に。失敗したら止めて報告）

### A. ビルド
- [ ] Android: `flutter build apk --debug` が通る（`minSdk = 29`）
- [ ] iOS: Xcodeで Runner がビルドできる（`AppDelegate.swift` の警告・エラーを確認）

### B. 取り込みとデコード（mp3 / m4a / wav）
- [ ] 各形式を「＋」で追加できる
- [ ] 曲をタップして「声除去済み」になる（ステレオ音源）
- [ ] モノラル音源は「処理できません」と出て落ちない
- [ ] DRM付き（.m4p）は拒否される
- [ ] 4分前後の曲でメモリ不足にならない（**要注意**: 現在は全サンプルをDartのdouble配列で保持。落ちるなら Float32 化が必要）

### C. 再生＋録音
- [ ] マイク許可ダイアログが出て、許可後に再生と録音が始まる
- [ ] 内蔵スピーカー、有線イヤホン、Bluetooth（車）の3経路で伴奏が鳴る
- [ ] Bluetooth接続中も入力が**内蔵マイク**（車のハンズフリーマイクにならない）
- [ ] 曲の最後まで再生したあと自動で終了し、次の曲へ進む

### D. 遅延測定
- [ ] 遅延補正画面の「自動測定」で値が出る（出力先ごとに保存される）
- [ ] 静かな場所で複数回測って、値のばらつきが±20ms以内
- [ ] 車のBluetoothで100〜300ms程度の値になる（目安。企画書の想定）

### E. 採点
- [ ] 伴奏に合わせて歌うと点数が出て、音声で読み上げられる
- [ ] 黙っていると低得点になる
- [ ] 別キー・オクターブ違いで極端に減点されない

### F. 車内モード（停車中の車で）
- [ ] 画面ロック／アプリを閉じても再生と録音が続く（Android: 通知が出る / iOS: バックグラウンド音声）
- [ ] Bluetoothの「次の曲」ボタンまたはステアリングのボタンで、採点なしで次へ進む
- [ ] 「前の曲」ボタンで同じ曲をやり直す
- [ ] 伴奏がマイクに回り込んでも、歌っていない区間が高得点にならない

### G. 未実装（この手順の対象外）
- 音声コマンド、近接センサー、速度による歌詞の自動非表示（現在は「停車中です」確認で代用）
- 課金（`in_app_purchase`）
